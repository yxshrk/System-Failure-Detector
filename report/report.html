Summary. On 174 functions (SP1) and 162 designs (SP2), scored exactly on gold models, we compare Claude Haiku 4.5, Sonnet 5.5 and Opus 5.5, and the open-weight Qwen 3.8 27B and Llama 3.1 8B, answering directly or translating for Z3, SATPlan and GBFS. For every model except Llama, SP1 is at ceiling for both arms at every trigger rarity, with no false alarms. In SP2 the 5.5 models find a valid trace every time in both arms, up to 51 events and even with mechanism names hidden, with no false alarms, and Qwen does so in Translate; translation cuts Haiku’s false alarms on correct designs from 60% to 35% (95% to 45% with hidden names; nominal paired p = 0.002, as designs share five templates). Llama 3.1 8B fabricates in Direct (no valid SP2 trace; false alarms on 76% of SP1 controls). Translation silences it rather than fixing it: its specifications and problem files are mostly unusable or incomplete, so it answers “safe” or nothing. Translation’s risks are specs that copy the bug, permissive models that planners exploit, and solver blow-up.

1. Motivation and research questions

A pre-mortem asks how a design will fail before it ships. Failures that matter are often reachable only through rare inputs or long event interleavings: model checking at AWS found a DynamoDB data-loss bug whose shortest trace had 35 steps, after it had passed design review, code review and testing [1]. An AI assistant for code and design review is therefore valuable only if it can produce witnesses, i.e. concrete failing inputs or event traces, and only if it does not fabricate failures that do not exist.

The GenAI lecture asks: “When should you use LLM reasoning directly? When should you translate problem specification then call tool?” (GenAI p.31). We compare two arms on the same inputs:

  • (A) Direct. The model reads the code (or design document) and answers with a verdict and a witness.
  • (B) Translate. The model writes a formal specification, and a classical solver searches for the witness (GenAI p.14). Solver errors are fed back for repair, as in Logic-LM [9] (PropLogic p.3) and the LLM+SMT method of the CSP lecture [5] (CSP p.17–18).

Arm B is the course’s case for a factored formulation (CSP p.6, p.12): once the structure is explicit, a general solver prunes what unstructured reasoning must enumerate.

In SP1 the object is one function and the witness a failing input; in SP2 it is a distributed-system design and the witness a failure trace; SP3 scores the translations themselves.

  • RQ1. Which arm finds more valid failure witnesses, and does the gap widen with trigger rarity (SP1) and with shortest-trace length (SP2)?
  • RQ2. Which arm fabricates more failures on correct controls?

2. Formulation

Both scales rest on α⊨β\alpha \models \beta iff α∧¬β\alpha \land \lnot\beta is unsatisfiable (PropLogic p.28, p.35; [3] Ch. 7), with α\alpha = “the system as implemented” and β\beta = “the requirement”. A model (PropLogic p.11) of α∧¬β\alpha \land \lnot\beta is a run that breaks the requirement: a failure witness. For a contract ∀x(pre⇒post)\forall x\,(pre \Rightarrow post), the negation is ∃x(pre∧¬post)\exists x\,(pre \land \lnot post) (FOL p.12), and the solver’s satisfying assignment to xx is the witness.

2.1 SP1: a function as a CSP, solved by SMT

CSP. Each instance is a CSP (X,D,C)(X, D, C) (CSP p.7).

  • Variables XX: the function’s inputs. An integer input is one variable. A list input is a length variable nn plus element variables e0,…,em−1e_0, \dots, e_{m-1}, where mm is the maximum length.
  • Domains DD: the stated ranges, e.g. 1≤month≤121 \le month \le 12, 0≤n≤m0 \le n \le m, and each ei∈[lo,hi]e_i \in [lo, hi]. Sorted or distinct lists add ordering or inequality constraints.
  • Constraints CC: ⟦f⟧(x,r)∧¬spec(x,r)\llbracket f \rrbracket(x, r) \land \lnot spec(x, r), where ⟦f⟧(x,r)\llbracket f \rrbracket(x, r) holds iff rr is what ff returns on xx.

The result rr and intermediate values are not separate variables: each is a shared sub-term of one formula DAG, fixed by the inputs, i.e. an auxiliary variable already eliminated (CSP p.13). The domains are finite, so this is a finite CSP, a class that is NP-complete (CSP p.8). Z3, however, receives SMT over unbounded integers (Int) with the bounds as ordinary constraints; products of variables and // or % by a variable make it non-linear integer arithmetic, undecidable in general. Our bounded queries are decidable, but Z3’s non-linear procedures are incomplete, so it can answer unknown (§5.1); a bit-vector encoding would reduce each query to SAT, at the cost of proving that no value overflows.

Building ⟦f⟧\llbracket f \rrbracket: bounded symbolic execution [12] (sp1/symexec.py). The proposal planned an off-the-shelf executor. We wrote our own because tools such as CrossHair explore paths under a time budget and report “no counterexample found” rather than proving unsatisfiability within a bound, which Theorem 1 needs. The executor walks the syntax tree once with a symbolic environment ρ\rho (variable → Z3 term) and a path condition π\pi (when control reaches the statement). x = e sets ρ[x]←⟦e⟧ρ\rho[x] \leftarrow \llbracket e \rrbracket_\rho. if c runs both branches, from (ρ,π∧c)(\rho, \pi \land c) and (ρ,π∧¬c)(\rho, \pi \land \lnot c), and joins them with ρ[x]=𝐼𝑓(π1,ρ1[x],ρ2[x])\rho[x] = \mathit{If}(\pi_1, \rho_1[x], \rho_2[x]) and π=π1∨π2\pi = \pi_1 \lor \pi_2 (break/continue likewise). return e sets ret←𝐼𝑓(π,⟦e⟧,ret)ret \leftarrow \mathit{If}(\pi, \llbracket e \rrbracket, ret) and π←⊥\pi \leftarrow \bot. An operation that raises when bb (bad index, x // 0, …) sets exc←exc∨(π∧b)exc \leftarrow exc \lor (\pi \land b) and π←π∧¬b\pi \leftarrow \pi \land \lnot b. A loop is unrolled kk times, iteration jj under π∧condj\pi \land cond_j, then unwind←unwind∨(π∧condk)unwind \leftarrow unwind \lor (\pi \land cond_k). The result is three terms over XX: retret, excexc (“raises”) and unwindunwind (“needs more than kk iterations”). Integers are unbounded and //, % follow Python’s floor semantics. Lists are values: aliasing (ys = xs; ys.sort()) is not modelled.

Lemma 1 (encoding correctness). For ff in the supported, alias-free subset, let x0∈Dx_0 \in D be an input whose execution needs at most kk iterations of every loop. Then unwind[x0]=⊥unwind[x_0] = \bot; exc[x0]=⊤exc[x_0] = \top iff f(x0)f(x_0) raises; and otherwise ret[x0]=f(x0)ret[x_0] = f(x_0). If the execution needs more than kk iterations, unwind[x0]=⊤unwind[x_0] = \top.

Proof sketch. Induction over statements, with the invariant: π[x0]=⊤\pi[x_0] = \top iff the concrete run on x0x_0 reaches this point, and then ρ[x][x0]\rho[x][x_0] is the concrete value of xx. Assignment preserves it; at an if exactly one branch condition holds at x0x_0, so the join selects the branch taken; return and raising operations record the outcome under the run’s path condition; and condkcond_k marks a (k+1)(k{+}1)-th iteration. ∎

The two queries. The model-written pre and post are compiled the same way, unrolled to k′=max⁡(k,L+1)k' = \max(k, L{+}1) where LL is the longest list input (doubled up to 4k′4k' while the coverage query Ψ\Psi below is satisfiable), and pre(x)pre(x) stands for “returns normally with a true value” (likewise postpost).

Φspec=D(x)∧¬unwindf∧¬unwindpre∧pre(x)∧(excf∨(¬unwindpost∧¬post(x,retf)))\Phi_{spec} = D(x) \land \lnot unwind_f \land \lnot unwind_{pre} \land pre(x) \land \big(exc_f \lor (\lnot unwind_{post} \land \lnot post(x, ret_f))\big)

Theorem 1 (soundness and bounded completeness). Suppose the coverage query Ψ=D(x)∧¬unwindf∧(unwindpre∨(pre(x)∧¬excf∧unwindpost))\Psi = D(x) \land \lnot unwind_f \land \big(unwind_{pre} \lor (pre(x) \land \lnot exc_f \land unwind_{post})\big) is unsatisfiable, i.e. on every input within ff’s bound the spec’s own loops fit k′k'. Then Φspec\Phi_{spec} is satisfiable iff some x0∈Dx_0 \in D within the bound satisfies prepre while ff raises or violates postpost (a prepre that raises counts as false, a postpost that raises as violated), and every model is such an x0x_0.

Proof sketch. By Lemma 1 on ff, prepre and postpost, each conjunct has its concrete meaning wherever the relevant function fits its bound; ¬Ψ\lnot\Psi says that it does at every input where it is evaluated. If Ψ\Psi is still satisfiable at 4k′4k', spec_check reports undecided, never “no failure”. ∎

Equivalently, Φspec\Phi_{spec} is unsatisfiable iff f⊨specf \models spec on all inputs within the bound: the entailment theorem applied to the bounded program. The same argument covers Φgold\Phi_{gold} with “behaves differently from the reference” for “violates the spec”. The build checks that no reference loop can exceed its bound, and accepts a mutant as equivalent only if its domain was enumerated or unwindmutunwind_{mut} is unsatisfiable.

The solver. Z3 [4], an SMT (“SAT modulo theories”) solver, decides satisfiability with DPLL(T): a DPLL core (PropLogic p.35) with conflict-directed backjumping (CSP p.40–41) searches the Boolean skeleton, and integer theory solvers return conflicts (clause learning is beyond the slides [4]). Every model is re-executed in Python before it counts, and Lemma 1 is tested: on every benchmark and hand-written mutant, the symbolic outcome must equal real execution on 25 random inputs (tests/test_symexec.py). Appendix B.1 shows a full instance.

2.2 SP2: a design as a STRIPS planning problem

STRIPS task (Planning p.7–11). Each family is a typed PDDL domain and each variant/size a problem; grounding (propositionalization, FOL p.17–19; up to KVK^V instances per schema, Planning p.10) gives Π=(F,A,I,G)\Pi = (F, A, I, G):

  • FF is the set of ground facts; a state s⊆Fs \subseteq F is the set of facts that hold (closed world assumption).
  • II is the initial state: design facts such as (dedup-racy), counters (next-tick t0 t1) and the starting situation. GG is the violation, e.g. {(charged-twice o1)}.
  • Each action a∈Aa \in A has pre(a)pre(a), add(a)add(a) and del(a)del(a). It is applicable in ss iff pre(a)⊆spre(a) \subseteq s, and then RESULT(s,a)=(s\del(a))∪add(a)\mathrm{RESULT}(s, a) = (s \setminus del(a)) \cup add(a) (Planning p.9).

A plan reaching sn⊇Gs_n \supseteq G is a failure trace. For example, accept-new-racy o1 a1 does not delete no-record o1, so a second request can pass the lookup before the first charge records the key (B.2 lists its prepre, addadd and deldel).

Modelling assumptions: events interleave one at a time; effects are deterministic and unconditional, preconditions and goals positive; the environment can do exactly the failure events in the domain (loss, delay, pauses, crashes, ticks); object counts, hence states, are finite. PlanSAT is PSPACE-complete [10] (NP-hard even without negative effects, Planning p.38); each SATPlan call decides bounded PlanSAT for one horizon TT, which is NP-complete for TT polynomial in the task size [10].

What a plan means here. The planner chooses every event, including loss, crashes and ticks, so a plan is a counterexample, not a course of action: planning serves as explicit-state model checking of a safety property. Liveness failures (an order never confirmed, starvation) are not STRIPS goals and are out of scope. “Safe” covers the instance at its size, not every size; we rely on the small-scope hypothesis [15], that most flaws already appear in small instances, and on an inductive invariant where search runs out (inventory from size 8, §6).

SATPlan encoding [6] (Planning p.31–37; planning/satplan.py). For horizon TT: a variable ftf^t per fact and step t≤Tt \le T, and ata^t per action and step t<Tt < T, with CNF clauses (PropLogic p.46):

  1. initial state: f0f^0 for f∈If \in I and ¬f0\lnot f^0 for f∉If \notin I;
  2. goal: gTg^T for each g∈Gg \in G;
  3. preconditions: at⇒pta^t \Rightarrow p^t for each p∈pre(a)p \in pre(a);
  4. effects: at⇒ft+1a^t \Rightarrow f^{t+1} for f∈add(a)f \in add(a), and at⇒¬ft+1a^t \Rightarrow \lnot f^{t+1} for f∈del(a)\add(a)f \in del(a) \setminus add(a);
  5. explanatory frame axioms: ft∧¬ft+1⇒⋁{at:f∈del(a)\add(a)}f^t \land \lnot f^{t+1} \Rightarrow \bigvee\{a^t : f \in del(a) \setminus add(a)\} and ¬ft∧ft+1⇒⋁{at:f∈add(a)}\lnot f^t \land f^{t+1} \Rightarrow \bigvee\{a^t : f \in add(a)\};
  6. exactly one action per step: the lecture’s exclusion axioms (Planning p.36) strengthened from at most to exactly one, encoded in linear size (sequential counter) instead of pairwise.

As a sound optimisation, facts that cannot yet be true (or false) at step tt become constants and actions that cannot yet apply get no variable (relaxed layers over-approximate reachability).

Lemma 2. Under (6), clauses (4)–(5) are equivalent to the lecture’s successor-state axioms Ft+1⇔ActionCausesFt∨(Ft∧¬ActionCausesNotFt)F^{t+1} \Leftrightarrow ActionCausesF^t \lor (F^t \land \lnot ActionCausesNotF^t) (Planning p.34). Proof. Let aa act at step tt. If f∈add(a)f \in add(a), (4) forces ft+1f^{t+1}; if f∈del(a)\add(a)f \in del(a) \setminus add(a), (4) forces ¬ft+1\lnot f^{t+1}; otherwise no active action adds or deletes ff, so (5) forces ft+1=ftf^{t+1} = f^t. Hence st+1=RESULT(st,a)s_{t+1} = \mathrm{RESULT}(s_t, a), with aa applicable by (3). ∎

Theorem 2. The horizon-TT formula is satisfiable iff a plan of exactly TT actions ends in a state containing GG, and the true action variables of a model form one. Iterating T=0,1,2,…T = 0, 1, 2, \dots up to the first satisfiable TT returns a shortest failure trace, so a violation is caught at the first step it holds, even if a later action would undo it; decoded plans are re-validated. UNSAT for all T≤TmaxT \le T_{max} proves only bounded safety.

Certifying safety: greedy best-first search with hFFh_{FF} (planning/search.py). hFF(s)h_{FF}(s) is the length of a relaxed plan for the task with delete lists ignored (Planning p.28), extracted from layered reachability (FF’s relaxed planning graph [7], beyond the slides), or ∞\infty if GG is unreachable even in the relaxation. GBFS expands states in order of hFFh_{FF}, never revisits one, tests for the goal on generation, and discards states with hFF=∞h_{FF} = \infty.

Theorem 3. If GBFS returns unsolvable, GG is unreachable from II. Proof. The state space is finite and each state is queued at most once, so the search terminates. When the queue empties, every generated state has been expanded or discarded and none was a goal. So any path from II to a goal would have to pass through a discarded state. Discarding is safe: ignoring delete lists only adds behaviour, so if GG is unreachable from ss in the relaxation, it is unreachable from ss in the real task. ∎

By the same argument GBFS finds a plan whenever one exists, though not always a shortest one (hFFh_{FF} is inadmissible, Planning p.25); FF’s hill-climbing phase (Planning p.28) is incomplete and cannot certify. Every fixed variant has finite hFF(I)h_{FF}(I), so certification needs the exhaustive search and hFFh_{FF} contributes only its dead-end test: on sizes 1–4 it expands 1.2× (cache) to 3.8× (queue) fewer states than plain BFS (inventory size 4: 9,026 vs 24,992), without changing the exponential growth. Pipeline: in the Translate arm GBFS decides reachability on the model’s problem; if a plan exists, SATPlan with TmaxT_{max} = the GBFS length returns a shortest trace (if its 120 s budget runs out, as in 17 inventory runs, the GBFS trace is kept). Appendix B.2–B.3 show real clauses, horizon iteration and a GBFS certificate.

What each arm translates. Both scales check α∧¬β\alpha \land \lnot\beta, but the model writes a different half: in SP1 it writes β\beta (pre/post) and the code α\alpha is encoded mechanically; in SP2 we fix β\beta (the goal, plus monitor actions such as charge-again) and the model writes part of α\alpha, the initial state with its design facts. The action schemas, where the failure mechanism lives, are given to both arms (§6).

3. Problem instances

3.1 SP1: 174 function instances

Benchmarks. 27 base functions, HumanEval/EvalPlus-style tasks [8] (below_zero, is_prime, …) plus business rules (calendar, grade bands, discounts, withdrawals), and 10 hard ones where a witness must be constructed (sorting networks, comparator medians, token-bucket rate limiters, a debouncer, Luhn, Zeller’s congruence, banker’s rounding, subset-sum DP). As planned, identifiers are renamed and docstrings rewritten without examples; each docstring fixes the return value on the stated domain, so the docstring is the specification.

Mutants and labels. The candidates are 808 automatic first-order mutants (ROR, AOR, CRP, LCR, condition negation, range off-by-one, statement deletion), 42 hand-written realistic bugs (a forgotten 400-year rule, a comparator dropped as an “optimisation”) and 9 equivalent rewrites.

Each candidate is labelled in four steps. Its trigger rarity is the probability that a random in-domain input exposes it (integers uniform; a list draws its length, then its elements, uniformly), computed exhaustively for integer domains up to 70k points and from 5,000 samples otherwise. Φgold\Phi_{gold} is then solved, every Z3 witness is confirmed by real execution, and equivalence is accepted only under the conditions of §2.1. Rarity buckets are common (≥10%), uncommon (1–10%), rare (0.1–1%) and very rare (<0.1%).

Selection. For each function we keep every hand bug, fill the rarity buckets with automatic mutants (preferring rare ones), and add two controls: the clean reference, plus an equivalent mutant when one exists. These are deliberately hard: dropping comparator (a, c) leaves a median-of-5 network correct.

Result. 174 instances: 115 bugs (67 common, 19 uncommon, 21 rare, 8 very rare) and 59 controls (37 clean, 22 provably equivalent). Of the 859 candidates, 59 were dropped as non-terminating, not encodable or not provably equivalent. The median Z3 query took 0.03 s (mean 0.2 s).

3.2 SP2: 60 designs, plus 30 stress, 60 opaque and 12 long variants

  • Opaque: the main set with design facts and design-specific events renamed (mode-2, accept-3) and their comments removed; the semantics are unchanged, but “racy” in the text no longer matches (dedup-racy) by name.

4. Method

Models. Claude Haiku 4.5, Sonnet 5.5 and Opus 5.5 with default extended thinking, called through the Claude Code CLI with all tools disabled (so Direct cannot run code). Two open-weight models served by SoC’s OpenAI-compatible endpoint (SoCLaaS) bracket them: Qwen 3.8 27B, which reasons before answering, and Llama 3.1 8B, which does not. Both run at temperature 0 with a 32k-token output budget that includes reasoning; Qwen ran SP1 and the SP2 main set only, as one SP2 answer took 5–10 minutes on the shared endpoint. Requests the endpoint dropped under load were resubmitted, not scored. Both arms see the same inputs:

  • SP1: the code with its docstring, plus the input domain.
  • SP2: the design document, the family’s PDDL domain (events, with comments) and object names.

Direct arm. JSON with a verdict and a witness: a failing input (SP1) or a list of ground actions (SP2).

Translate arm, SP1. The model writes pre(...) and post(..., result) in the supported Python subset, stating the docstring’s intent, not the code’s behaviour; spec_check then runs.

Translate arm, SP2. The model writes the PDDL problem. Object names and the goal are given, so the translation is the complete initial state, including design facts and counters; mapping prose to one design fact per mechanism is the semantic step SP3 scores; the pipeline of §2.2 then solves it.

Repair loop. Errors are fed back up to twice: syntax errors, unsupported constructs, a vacuous precondition, a wrong goal, type or arity errors: a harness with verification and retries (GenAI p.28).

Tool budgets. An SP1 spec check has a 120 s deadline in a child process killed after 150 s; Z3 queries time out at 60 s; planner search is capped at 3 M expansions or 300 s, SATPlan at 120 s. A budget hit, a Z3 unknown or a failed coverage check (Ψ\Psi satisfiable) is reported as undecided, never as “no failure”.

Scoring is exact, on gold models: an SP1 witness is valid only if it is in-domain and the code under review and the unmutated reference behave differently on it; an SP2 trace is valid if replaying it on the gold problem reaches the violation.

Outcomes are valid witness, fabricated (an invalid witness or a false alarm on a control: a hallucination made checkable, GenAI p.9), miss, correct no-failure, or undecided (the tool gave up; counted as no answer). Every LLM response is cached, so all numbers can be regenerated offline.

6. Analysis and insights

SP1: localisation, not search. A first-order mutant leaves a visible diff against a docstring that states the intent, and reading code is white-box, so trigger rarity, which decides whether testing finds a bug, showed no detectable effect on either LLM arm (Fig. 1). In Kang et al.’s terms [2] (GenAI p.18), base-tier SP1 is the easy case: the next step (find the line contradicting the docstring) is cheap, so the chain of thought stays short. The hard tier, where a witness must be constructed, moves towards the search case; the models paid 2–3× more tokens rather than failing: our functions are small enough for a linearised search.

SP1: translation moves the risk into the specification. The spec must state the docstring’s intent while the model reads code that contradicts it: twice the postcondition inherited the bug (§A.2), and once a broken spec produced a fabricated witness (§A.3), both invisible to a solver faithful to the spec. Nearly every spec is constructive: post recomputes the answer and compares it with result (169–172 of 174 per model). SP1 Translate is thus a differential check against a second, model-written implementation (N-version programming), which is why a spec can inherit the bug it should expose. The repair loop fixes form (Haiku 106 → 112, Opus 104 → 114 of 115) but not meaning; specs should be written blind to the code, or checked against known input/output pairs.

SP2: the jagged frontier runs between model generations. The 5.5 models are never wrong in either arm on all four sets (Translate is undecided only where certification runs out of budget, §5.3). Haiku’s Direct errors are not slips in long traces but design misreadings (§5.2): it applies a well-known pattern, such as the check-then-act race, to a design whose text rules it out (§A.4).

Translation does not remove misreading; Haiku moves the same mistake into the design facts it writes, and adds permissive initial facts that the planner turns into shortcuts (§A.5): a classical planner is adversarial towards its model. Still, Haiku’s false alarms roughly halved, at lower cost.

Open weights: a floor below which translation silences instead of fixing. Qwen 3.8 27B, free on SoC’s endpoint, matches the 5.5 models on SP1 and on the SP2 main set in Translate, and in Direct differs only by three format slips, at the cost of reasoning (about 8–10k output tokens and 5–10 minutes per SP2 Direct answer on a shared GPU). Llama 3.1 8B, which does not reason, fabricates in Direct: witnesses that do not reproduce, and traces whose events have the wrong names or arity (37 of 48 classified failures on the main set). Translation does not repair this; it silences it. Llama cannot write the formal language reliably (70 of 174 SP1 runs end with no accepted spec, 8 of 60 SP2 problems never parse), and what it writes is incomplete: problem files missing a third of the initial state make flawed and fixed designs alike look safe, and unsound specs cause all of its SP1 false alarms. The solver is faithful to an under-constrained model that rarely admits any failure, so false alarms fall for the wrong reason. Against the trivial policy “always answer safe” (no false alarms, every violation missed), Llama Translate on the SP2 main set adds one valid trace and two false alarms. “Translate when the model is weak” thus holds only above a floor: the model must write the formal language correctly and completely, and SP3’s recall, not the solver, is where a weak model fails.

Length vs. familiarity. Our violations are textbook patterns; once one is recognised, a longer trace is bookkeeping. From 6–15 to 30–51 events the 5.5 models found a valid trace on every violating design, and their Direct answers grew only from about 1.2k to 1.5k output tokens (Haiku’s per-length cells hold 2–16 designs). With design facts renamed mode-N, they were still never wrong, so they map the mechanism described in the text, not just its name. Haiku leans on names: its Direct false alarms rose from 60% to 95%. Translate held it to 45%: writing the initial state forces one design fact per mechanism.

The tools have cliffs too (§5.3). SATPlan’s horizon iteration slows on symmetric interleavings, exhaustive certification explodes with the state space, and bounded symbolic execution ignores paths beyond the bound. The standard remedies lie outside the course: symmetry reduction (merging states that differ by a permutation of interchangeable objects, such as inventory’s customers) and partial-order reduction (one order for independent events, Planning p.9), both in TLC and SPIN; CBMC’s unwinding assertions, which check that unwindunwind (§2.1) is unsatisfiable; and inductive invariants (k-induction with k=1k = 1), which prove safety by entailment (PropLogic p.28) with three checks: Inv(s0),Inv(st)∧T(st,st+1)⊨Inv(st+1),Inv⊨¬G.Inv(s_0), \qquad Inv(s_t) \land T(s_t, s_{t+1}) \models Inv(s_{t+1}), \qquad Inv \models \lnot G. Inventory’s label from size 8 rests on one, proved by hand: stock + holding + sold = S. Initially stock = S; reserve-atomic moves a unit from stock to holding, expire-hold moves it back, pay moves it to sold, and the other actions change no count or are disabled by the fixed design facts; each customer leaves browsing once, so no count rises twice. Hence sold ≤ S < S + 1. Our search cannot certify a Direct “safe” there either, and the tool says “undecided”.

Is translating worth it? A decision rule. Choosing an arm is a maximum-expected-utility decision (Decision p.16). With a share π\pi of flawed designs and costs cFAc_{FA} per false alarm (reviewer time), cmissc_{miss} per flawed design left without a valid witness, crevc_{rev} per undecided case left to a reviewer, and crunc_{run} per run (model-call charges only; solver time and human review are extra), EU(arm)=−((1−π)PFAcFA+πPmisscmiss+Pundcrev+crun).EU(arm) = -\big((1-\pi)\,P_{FA}\,c_{FA} + \pi\,P_{miss}\,c_{miss} + P_{und}\,c_{rev} + c_{run}\big). For Haiku on the SP2 main set, Translate has fewer false alarms (35% vs 60%), fewer flawed designs without a valid trace (6 vs 9 of 40), nothing undecided and the lower cost (US$0.051 vs 0.062), so under this loss and these rates it wins for any π\pi and positive costs; on the opaque set it trades two detections for half the false alarms. Llama’s Translate also has both lower rates than its Direct (10% vs 70% false alarms; 39 vs 40 flawed designs without a valid trace), yet beats “always safe” only if a miss costs more than four false alarms (at π=1/2\pi = 1/2, ignoring review of its no-answers), and then by a single trace. For the 5.5 models on SP2 the error rates are zero, so cost meets abstention: Translate is cheaper and wins outright on the main set, but is undecided on inventory’s fixed design from size 8, where Direct answers correctly. On SP1, Opus’s Translate is dearer and leaves one bug and five controls undecided, so Direct wins; Sonnet’s small model-call saving must be weighed against one unresolved faulty instance and its review cost. Only Translate can certify absence, with a solver result and audit trail that hold relative to the translated model. Direct suffices when the specification is local and explicit, the artefact small and the model strong (SP1 at every tier; SP2 for the 5.5 models, even with opaque names). Translate’s weaknesses are specification correctness and the tools’ state-space and term-size limits.

Direct accuracy on problems of this size may keep rising, as the step from Haiku 4.5 to the 5.5 models suggests. But “computationally difficult problems [are] likely to remain difficult” (GenAI p.31). Even 51-event designs did not reach that regime for the 5.5 models; inventory from size 8 did for the tools.

Threats to validity.

  • Mutants. They are small, first-order faults [13]; real bugs often span several lines. Some automatic mutants are unidiomatic (if not x not in out) and hint at the mutated line, yet Direct also found 41–42 of the 42 cue-free hand-written bugs.
  • Specifications. Docstrings are complete; vaguer real ones would hurt Translate more. Functions were selected to be encodable (integers, Booleans, lists; no strings, floats or recursion), favouring the tools.
  • Familiarity and contamination. The SP1 functions derive from public benchmarks, and renaming mitigates but does not remove contamination. The SP2 families are textbook patterns; the opaque ablation removes lexical cues, not conceptual familiarity.
  • Authorship. The design documents and gold models were produced together, not independently; two documents contradicted their models and were corrected, with all affected instances rerun.
  • Scaffolding: the event model gives the mechanism away. The given action schemas contain each failure mechanism as a named, guarded event (accept-new-racy does not delete no-record), so SP2 Translate reduces to choosing one or two design facts per family, and that choice decides the outcome: correct in 47/49 (Haiku) and 60/60 (5.5 models, Qwen) main-set problems with exact facts, 0/11 (Haiku) with wrong ones. Writing the event model (Planning p.15), as in [11], is untested.
  • Sampling and configuration. Each instance is sampled once, instances share five templates (so intervals and p-values are nominal), and many cells are at ceiling. Models ran with default thinking budgets, so generations also differ in effort (Haiku used 10–15k tokens, the 5.5 models about 1k). The open-weight models ran at temperature 0 with a 32k-token budget; Qwen ran SP1 and the SP2 main set only, and lost 4 SP1 Translate answers to the endpoint’s 15-minute stream limit.

7. Responsible AI

Automation bias: what “no failure” means. A verdict is a belief about a model, not a fact about the world (ProbGrapModel p.4): SP1 certifies only within the domain and unroll bounds (Theorem 1), and SP2 only within the event model, so a failure mode the domain lacks is invisible to both arms. We therefore say “no counterexample within the input and loop bounds” (SP1) or “no reachable violation in this finite event model” (SP2), never “verified safe”, which certainty and framing effects (Decision p.24–25) predict reviewers over-trust. Skipping manual review is rational only if P(hidden failure | “no failure”) is below review cost divided by incident loss (Decision p.15–16, if review would catch the failure). On our SP2 main set, 2 of Haiku Direct’s 10 “safe” verdicts were wrong and none of Haiku Translate’s 13 (95% upper bound 23%); both depend on the base rate of flawed designs (Bayes’ rule, ProbGrapModel p.24–25) and miss failure modes outside the benchmark.

Fabricated failures. False alarms waste reviewer time and train reviewers to ignore the tool, a trade-off against misses set by their utilities (Decision p.15–16). A Translate witness is correct only with respect to the model’s own specification: 13 of Haiku’s main-set SP2 Translate traces (40 across all sets) were legal only in its mistranslated problem, as the planner optimises the model as written, not as meant (the King Midas problem, ResponsibleAI p.35). Witnesses must therefore be executed or replayed on the real artefact, as our scoring does.

Accountability. Translate leaves an audit trail (spec, solver log, witness), close to a white-box explanation (ResponsibleAI p.24). A named engineer can then sign off on what was checked. Direct answers are post-hoc narratives (ResponsibleAI p.25–26). Responsibility stays with the humans who sign off (ResponsibleAI p.6): the tool supports a human–AI review team rather than replacing the reviewer (ResponsibleAI p.45).

Dual use and attacks on the reviewer. A witness can help construct an exploit, and AI lowers the cost of attacks (ResponsibleAI p.2–4); we would run the tool only on code the user owns, follow coordinated disclosure, and withhold witnesses for unpatched deployed systems. A comment planted in the code could steer the Direct arm to “no bug” (ResponsibleAI p.31); Translate may be less exposed, since the solver decides, but its spec is still model-written (untested). Sending proprietary code to a hosted model also discloses it (ResponsibleAI p.8–10); on-premise open-weight models avoid that, and Qwen 3.8 27B on SoC’s own endpoint was as accurate as the hosted 5.5 models on SP1 and the SP2 main set.
